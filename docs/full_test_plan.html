Part 0 — Environments, roles & one-time setup

0.1 Roles

RoleResponsibility

0.2 One-time setup

#StepWhy
0.1Uninstall older Hiraal builds, then install the release APK.Release-signed builds can't upgrade over debug-signed ones.
0.2Grant Nearby devices (Bluetooth), Location, Notifications when asked.BLE scan/connect and alerts depend on them.
0.3Bluetooth ON; devices charged, unpaired from other apps/phones, and close by.A BLE device stops advertising while connected elsewhere — force-close vendor apps (e.g. Andesfit) first.
0.4Verifier: open the lists Daily Reading, Chronic Care Alert, Medicine Request, Care Subscription, Subscription Payment, Notification Log.These are the "source of truth" for most tests.
0.5Have a registered test patient (phone + email) and a small mobile-money wallet (ZAAD/eDahab). Payments are live — use the smallest possible amounts.End-to-end tests move real money.

0.3 Environments

EnvironmentHow to get itNotes
Live (UAT)Default release APK buildReal OTP (SMS/email), real payments, real server data.
Mock (offline demo)Dev build with --dart-define=USE_MOCK=trueNo backend needed; all data is simulated. Use for UI regression only.
Web debug harnessdart tools/uat_proxy.dart + web build pointing at localhost:8090Single-origin proxy to UAT with full request/response logging — fastest way to see exact server errors.

0.4 Supported devices (BLE)

Standard Bluetooth SIG profiles (Blood Pressure 1810/2A35, Glucose 1808/2A18, Weight Scale 181D/2A9D) and Andesfit B180 (proprietary fff0). Built-in name detection covers: Omron, A&D (UA-651), Accu-Chek, Contour, Andesfit. Detection order: advertised name/UUIDs → GATT table re-detect → per-characteristic fallback.

Test-data hygiene: record the exact time of every measurement/payment you make. The verifier uses timestamp + patient + values to find the exact record.

Part 4 — Known limitations & bug reporting

Known limitations (by design or pending work)

AreaLimitation
AppointmentsRequires a consulting charge configured per practitioner ("OP Consulting Charge"), or booking errors. Admin setup task.
Auto-renewalNo silent mobile-money auto-debit — patients get a pay reminder instead. Intended.
RemindersDaily local notifications use inexact alarms (no exact-alarm permission) — fire time can drift a few minutes under battery optimization.
PaymentsSubscription push completion can't be matched to a specific transaction id server-side yet (payload carries the subscription name only).
Analytics pageSome desk analytics metrics are placeholder values (engagement score etc.).
iOSNot currently built/tested (plist keys are in place).

How to report a problem

For each failure capture:

1. Test ID (e.g. C-10) and the exact steps taken.
2. Expected vs actual.
3. Screenshot or screen recording (especially payment/measuring screens).
4. Exact values: reading numbers / order id / amount / time (for server tracing).
5. Phone model + Android version + build date of the APK.
6. ERPNext side: Error Log entries + the relevant doctype record id.
